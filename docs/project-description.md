# AI-агент для детекции аномалий в телеметрии спутников

## Аннотация

Современные спутники генерируют огромные объёмы телеметрических данных — тысячи параметров ежесекундно. Штатная система мониторинга, основанная на жёстких пороговых правилах, пропускает значительную часть аномалий, которые проявляются как нехарактерные паттерны внутри допустимых диапазонов. Оператор спутниковой связи вынужден вручную просматривать десятки графиков в день, что требует высокой квалификации, внимательности и временных затрат, а критическая аномалия может быть пропущена из-за человеческого фактора.

Представленный проект предлагает решение на основе LLM-агента с архитектурой ReAct (Reasoning + Acting), который автоматизирует первичный анализ телеметрии. Оператор взаимодействует с системой через чат-интерфейс на естественном языке: задаёт вопросы, получает сводки, уточняет детали. Агент самостоятельно выбирает набор инструментов для каждого запроса — детекцию всплесков (spikes), поиск сдвигов тренда (CUSUM), проверку границ диапазонов, анализ методами машинного обучения (PyOD).

Система построена на фреймворке LangGraph (Python), который обеспечивает графовую оркестрацию вызовов LLM и инструментов с поддержкой потоковой передачи (SSE). Фронтенд реализован на Svelte 5 с использованием @langchain/svelte SDK для нативного стриминга ответов. Развёртывание осуществляется через Docker Compose (Python-агент + nginx). В качестве источника данных используется открытый набор OPS-SAT-AD Европейского космического агентства (ESA) — ~300 000 точек телеметрии с бинарной разметкой аномалий.

В ходе разработки было реализовано семь инструментов анализа, модуль кросс-канальной корреляции и автоматическая генерация ежедневных отчётов с ранжированием аномалий по композитной оценке severity. Интерфейс позволяет оператору в реальном времени просматривать графики телеметрии и детализацией по каждому инструменту.

Ключевой результат — снижение порога входа для анализа телеметрии: оператору больше не нужно помнить сигнатуры аномалий и параметры детекторов. Система берёт на себя «первую милю» анализа, оставляя человеку принятие решений по выявленным событиям. В перспективе решение может быть адаптировано под другие источники телеметрических данных (наземный транспорт, промышленное оборудование, ЦОД) и дополнено предиктивной аналитикой.

## Проблематика

**Актуальность.** В спутниковой связи телеметрия — единственный канал получения информации о состоянии бортовых систем. Пропущенная аномалия может привести к потере спутника или снижению качества услуг. Существующие системы мониторинга используют пороговые правила (например, «выход температуры за предел 85°C»), но не обнаруживают аномалии, связанные с изменением характера сигнала: внезапный рост шума, нарушение стационарности, учащение микровсплесков внутри нормы.

**Болевые точки текущего процесса:**

- Ручной просмотр десятков графиков телеметрии в день — трудозатратно и подвержено человеческому фактору
- Отсутствие единого инструмента, объединяющего статистический, ML и визуальный анализ
- Высокий порог входа для новых операторов (требуется знание сигнатур аномалий по каждому каналу)
- Невозможность быстро получить сводку «что случилось за сутки» по всем каналам на естественном языке

**Последствия откладывания решения:** рост числа пропущенных инцидентов, увеличение time-to-detection, необходимость найма дополнительных операторов по мере расширения спутниковой группировки.

## Постановка задачи

Разработать интеллектуального AI-агента для автоматизированной детекции аномалий в телеметрии спутников со следующими требованиями:

1. **Интерактивный чат-интерфейс** — оператор задаёт вопросы на естественном языке и получает структурированные ответы с визуализациями
2. **Множественные методы детекции** — статистические тесты (ADF на стационарность, MAD для спайков), CUSUM для сдвигов тренда, ML-детекторы (PyOD), проверка номинальных диапазонов
3. **Визуальная диагностика** — генерация графиков с подсветкой аномалий
4. **Кросс-канальный анализ** — сравнение поведения нескольких каналов на одном интервале
5. **Автоматическая генерация отчётов** — ежедневное сканирование всех каналов с ранжированием аномалий

## Описание технического решения

### Архитектура

Система состоит из двух основных компонентов:

```
┌─────────────┐    SSE stream     ┌─────────────────────────┐
│  Svelte 5   │ ◄──────────────►  │  LangGraph Agent Server │
│  Фронтенд   │   POST /runs      │  (Python 3.12)          │
│  (nginx)    │                   │  ┌───────────────────┐  │
└─────────────┘                   │  │ ReAct Agent       │  │
                                  │  │ call_model →      │  │
                                  │  │ run_tools → loop  │  │
                                  │  └───────────────────┘  │
                                  └─────────────────────────┘
```

### Агент (ReAct Loop)

Агент реализован на LangGraph и работает по циклу Reasoning + Acting:

1. **call_model** — LLM получает историю диалога и решает, какие инструменты вызвать
2. **run_tools** — выполняет выбранные инструменты, возвращает результаты
3. **should_continue** — если модель запросила ещё инструменты, цикл повторяется; иначе ответ возвращается пользователю

### Инструменты агента (6 шт.)

| Инструмент              | Назначение                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `list_segments`         | Список доступных каналов и временных окон                                                                        |
| `analyze`               | **Ядро детекции:** профиль стационарности, MAD-спайки, CUSUM-сдвиги, проверка диапазонов, PyOD (6 ML-детекторов) |
| `compare_channels`      | Кросс-канальная корреляция и синхронный анализ аномалий                                                          |
| `visualize`             | Построение графика временного ряда (base64 PNG)                                                                  |
| `generate_daily_report` | Сканирование всех каналов за дату, композитный score аномалий                                                    |
| `get_anomalous_hours`   | Детализация аномальных окон за день с фильтрацией по каналу                                                      |

### Методы детекции аномалий

- **Spikes (MAD):** медианное абсолютное отклонение с порогом 3.5 sigma, фильтрация по peak prominence
- **Trend shifts (CUSUM):** кумулятивная сумма отклонений, порог и drift — конфигурируемы
- **Range check:** P01–P99 номинальные границы из обучающей выборки, IQR fallback
- **PyOD ML:** TimeSeriesOD с детекторами IForest, HBOS, KNN, LOF, PCA, OCSVM

### Фронтенд

Svelte 5 SPA с @langchain/svelte SDK. Потоковый приём сообщений (SSE), рендеринг Markdown + KaTeX + base64-изображений, карточки вызова инструментов с отображением статуса, входных параметров и результатов. Тёмная тема, адаптивный дизайн.

## Полученные результаты

**Основные достижения:**

1. **Разработан и развёрнут полностью функциональный AI-агент** с 6 инструментами анализа, работающий в архитектуре ReAct на LangGraph
2. **Реализовано 4 метода детекции аномалий:** MAD-spikes, CUSUM-shifts, range check, ML (PyOD) — покрывающие разные типы отклонений
3. **Реализован кросс-канальный анализ** с расчётом корреляции Пирсона между каналами
4. **Автоматическая генерация ежедневных отчётов** с композитным score аномалий и ранжированием по severity
5. **Современный чат-интерфейс** с потоковым стримингом, поддержкой Markdown/KaTeX и отображением визуализаций
6. **Контейнеризация:** Docker Compose (agent + nginx)

**Количественные метрики:**

- Покрытие: все каналы датасета, любые 1-часовые окна
- Время ответа: потоковый SSE — первый токен менее 1 секунды

**Качественные результаты:**

- Оператор получает единую точку входа для анализа: чат вместо переключения между десятком утилит
- Система объясняет _почему_ сегмент помечен как аномальный (какой тест не пройден, какие точки выбиваются)
- Визуализация с подсветкой аномалий даёт оператору мгновенное понимание характера проблемы

## Дальнейшие планы по развитию

1. **Предиктивная аналитика** — добавление моделей прогнозирования временных рядов (SARIMA, Prophet) для обнаружения отклонений от прогноза
2. **Поддержка других источников данных** — data loader для подключения к реальным телеметрическим системам через API
3. **История сессий и экспорт** — сохранение истории диалогов, экспорт отчётов в PDF
4. **Система уведомлений** — проактивные-оповещения при обнаружении аномалий критического уровня, автономный режим мониторинга
5. **A/B тестирование методов** — возможность настройки и сравнения конфигураций детекторов
